# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Lightweight self-hosted Discord music bot (YouTube only for now), CommonJS Node.js. Target host is Wispbyte free tier (512MB RAM / 1GB disk), so keep memory and disk small.

## Commands

```bash
npm install
npm run deploy         # register slash commands (re-run whenever a command's name/options change)
npm start              # node --max-old-space-size=256 --max-semi-space-size=1 src/index.js (the semi-space flag saves ~13 MB idle / ~30 MB after bursts)
npm run selftest       # config + helpers + network + a real YouTube lookup, without connecting to Discord
npm run update-ytdlp   # manually refresh bin/yt-dlp
npm run check          # syntax-check all src/ and scripts/ files (no linter)
npm test               # node:test unit tests in tests/ (pure logic only; voice needs a human)
node --test tests/embeds.test.js   # single test file
```

Planned work lives in `docs/ROADMAP.md`; agent workflow rules are in `AGENTS.md`.

Config comes from `.env` (see `.env.example`): `DISCORD_TOKEN`, `CLIENT_ID`, optional `GUILD_ID` (instant guild-scoped command registration), `YTDLP_COOKIES`, `IDLE_LEAVE_MINUTES`, `BOT_OWNER_ID`, `MEMORY_LIMIT_MB`, `LOG_LEVEL`/`LOG_FILE`/`LOG_MAX_MB`/`LOG_KEEP`, `YTDLP_JS_RUNTIME` (all documented in `.env.example`).

## Architecture

Audio pipeline: normal playback uses `yt-dlp` stdout (`-o -`) -> `ffmpeg` (ffmpeg-static, encodes `libopus` into Ogg) -> `createAudioResource(..., StreamType.OggOpus)`. For non-live seeks, yt-dlp resolves a direct audio URL so ffmpeg can seek efficiently. Stream options (`seek`, `filters`, `volume`) are passed per guild; `buildFfmpegArgs()` keeps ffmpeg construction pure and testable. Opus encoding happens in ffmpeg, never in JS, and nothing touches disk.

- `src/index.js` - client with minimal intents/caches, routes slash commands by name, loads persistent settings before login, downloads yt-dlp on first run and refreshes it every 12h (YouTube breaks old versions often); graceful shutdown flushes settings, playlists, and queues with a bounded 5-second timeout.
- `src/store.js` - per-guild JSON settings with defaults (DJ role, command channel, default volume, 24/7, queue and duration limits), debounced atomic writes, and corrupt-file backup. `/settings` is ManageGuild-only; `src/music/permissions.js` is the pure DJ/channel authorization policy. `createStore()` accepts a file path for isolated tests; the exported singleton uses `data/settings.json`.
- `src/commands/index.js` - loads each command module in `src/commands/` (skipping `index.js` and underscore-prefixed helper files); each command exports `{ data, execute }`. Shared `needQueue()` and `reply()` helpers live in `src/commands/_util.js`. Replies use embeds from `src/embeds.js`. `/seek` and `/restart` share `src/commands/_seek-util.js`; pure time parsing lives in `src/music/time.js`.
- `src/embeds.js` - shared Discord embeds and duration formatting; Now Playing includes a static progress snapshot rendered by pure `src/music/progress.js`, plus reusable control-button rows.
- `src/music/player.js` - `GuildQueue` per guild (module-level `queues` Map): owns the voice connection, `AudioPlayer`, track list, loop mode, playback options, seek offset, and idle-leave timer. It also keeps only the latest now-playing message reference and disables its controls when playback advances/stops. Queue mutations (`remove`, `move`, `shuffle`, `clearQueue`, `skipTo`, `playNext`) operate on upcoming tracks and use 1-based public positions; pure operations live in `src/music/queue-ops.js`. State machine: player `Idle` -> `onIdle()` -> `advance()` -> `play()`. `enqueue()` returns `true` when playback starts immediately; `/play` uses that to show only a "Now playing" embed instead of "Queued". `src/music/queue-policy.js` enforces per-guild queue length and track duration limits on enqueue/play-next. In 24/7 mode, idle timeouts and empty-channel auto-leave are suppressed. `src/music/queue-store.js` atomically persists bounded queue snapshots (<=100 tracks), checkpoints elapsed position every 30 seconds, restores saved queues after startup, preserves lazy Spotify `spotifyQuery` identity and restores via YouTube search, and skips tracks that fail to resolve. Playlist/favorite saves retain the Spotify search query rather than the album URL. `src/music/rate-limit.js` provides the 3s per-user `/play` and `/search` cooldown and a global two-resolution limiter. `src/memory-watchdog.js` checks RSS every 60s (default warning 420 MB via `MAX_RSS_MB`), clears autocomplete/SponsorBlock/prefetch caches, invokes GC if available, and exits nonzero over 480 MB. `src/log.js` provides timestamped level-based logging controlled by `LOG_LEVEL`; playback logs guild/source/resolve time. `src/music/presence.js` rotates activity every 30s between a sole playing title and `/play | N servers`. The yt-dlp updater validates >5MB and `--version` before a backup-preserving atomic swap; extractor errors may trigger one update/retry per hour. `src/log.js` provides timestamped level-based logging controlled by `LOG_LEVEL`; playback logs guild/source/resolve time. `src/music/presence.js` rotates activity every 30s between a sole playing title and `/play | N servers`. The yt-dlp updater validates >5MB and `--version` before a backup-preserving atomic swap; extractor errors may trigger one update/retry per hour. `play(track, silent, opts)` stores per-guild volume and filters; `restartCurrent(opts)` restarts the current stream without advancing the queue. `getElapsedSeconds()` includes the current stream's seek offset. `skip()` sets a `skipping` flag so `loop track` doesn't replay the skipped song. A stream that errors before output gets one retry using yt-dlp's alternate `ba*` format.
- Play latency: every yt-dlp launch costs ~1.3s on Windows (PyInstaller exe) plus ~2.5s of extraction, so `youtube.resolve()` does ONE call for single videos/search text (`--print` JSON with metadata + direct audio URL, `skip=hls`) and stores `prefetchedAudioUrl`/`audioCodec`/`audioUrlExpiresAt` on the track; `stream()` feeds that URL straight to ffmpeg (stale URLs are discarded, failures fall back to the yt-dlp pipe/`ba*` retry). Opus sources are remuxed with `-c:a copy` unless filters/volume apply; ogg pages flush every 20ms. Playlists/mixes still use the flat resolve.
- Interactive views (Discord components): `src/music/pager.js` (pure pagination), `list-view.js` (shared paginated embed/nav/collector for `/playlist show`, `/history`, and plain-text `/lyrics`; requester-only, shared prefix parameter), `queue-position-autocomplete.js` (memory-only position choices for `/remove`, both `/move` positions, and `/skipto`, capped at 25), `queue-view.js` (`/queue` + Now Playing Queue button; re-reads the live queue per click, provides page-local track selection and selected Remove/Play now/Move to top plus Shuffle/Clear/Loop/Autoplay actions; action callbacks use the existing `queue:` collector and enforce `canUse` for restricted operations). `GuildQueue` owns one `live-progress.js` timer that updates a finite-track announcement every 15s only while playing with non-bot listeners; pause/idle/skip/stop/destroy stop it, and edit failures end it. `search-view.js` + `commands/search.js` (YouTube/SoundCloud search, two pages of 8 numbered results, Queue all), `collection-view.js` + `commands/_collection-prompt.js` (any multi-track result: play all / shuffle / first only / play next / save / cancel; also used by `/favorites` and `/playlist play` with `allowSave:false`), `collection.js` (pure: summarize, order/shuffle, unique playlist names). Each owns a customId prefix (`queue:`, `search:`, `collection:`) handled by a message collector, not by `src/index.js`; `np:` buttons are routed in `index.js`. YouTube playlists load up to `PLAYLIST_LIMIT` (200) tracks; saved playlists/favorites use `loadSavedTracks` (no per-track yt-dlp calls).

Command replies that start playback use `src/commands/_card.js` (`replyWithCard`) so the reply itself becomes the live card (`adoptAnnouncement`); the card collapses to "Finished: ..." (setting `cleanupNowPlaying`: edit/delete/keep). `src/music/format.js` has `fmt` (durations, 0 = Live) and `formatClock` (positions, never "Live"); `title.js` cleans titles for display only. `np:` buttons are handled by `src/np-controls.js`. The request channel (`/setup-player`) is a persistent message (`jukebox-view.js`, throttled updater `jukebox.js`, buttons `jb:` in `src/jukebox-controls.js`, Add song modal); inside that channel per-track announcements are skipped. After restart `ClientReady` re-attaches it.
- `/stats` memory: `src/music/helper-memory.js` reads the yt-dlp/ffmpeg processes by name (tasklist / `/proc` / ps), because the host RAM limit counts them but `process.memoryUsage()` only sees Node; it shows per-helper counts and `Total ≈ X MB of MEMORY_LIMIT_MB` (default 512; flags 🟡 at 70%, ⚠️ at 85%). Measured on Windows: Node ~105 MB, yt-dlp ~87 MB while resolving, ffmpeg ~20 MB per playing server.
- Operations (startup, logs, safety): `src/startup-check.js` (pure config checks run at start and by `npm run selftest`/`/admin selftest` via `src/selftest.js`: Node version, token shape, voice library >= 0.19 + DAVE, an intact discord.js (creates a Client; a file deleted from node_modules once crashed startup), ffmpeg/yt-dlp, cookies, data folder; errors stop the bot with a clear message, the token is never printed; a rejected login exits with a hint). `src/log.js` has listeners; `src/log-file.js` writes `data/logs/bot.log` (size-rotated, bounded, never throws) and `src/error-alerts.js` DMs `BOT_OWNER_ID` when the same error repeats (3x/10 min) or 10 different ones happen; `/admin logs|selftest|cookies`. `src/process-registry.js` tracks every yt-dlp/ffmpeg the bot spawns: killed on exit (Windows keeps orphans otherwise, killed as a tree) and swept when older than their max age (radio is exempt). `src/music/voice-access.js`: `getOrCreate` refuses to join a channel the bot cannot view/connect/speak in (or a full one) with the exact reason, and a server-mute is announced once. yt-dlp JS runtime: a lookup that fails for an unexplained reason is retried once with `--js-runtimes node:<execPath>` (`YTDLP_JS_RUNTIME=auto|always|off`). Radio streams get the same leveling/EQ/volume as songs (tempo filters dropped via `liveSafeFilters`) and reconnect on drops. `/undo`: `GuildQueue.remember()` snapshots the track list BEFORE each successful change (`src/music/undo-stack.js`: 10 steps, 10 minutes, cleared on stop/leave). - `src/music/sources/youtube.js` - the source interface is `{ name, resolve(query) -> Track[], resolveMany(query, n) -> Track[], stream(track, opts) -> Promise<{ stream, kill }> }`; yt-dlp and ffmpeg failures are explicitly forwarded to the returned Transform because errors do not propagate through `.pipe()`, and ffmpeg URL inputs use an HTTP(S)-only protocol whitelist; the generic URL source pre-resolves DNS and blocks private/reserved IPv4, IPv6 (including mapped, NAT64, and 6to4 forms), but redirects and DNS rebinding are not pinned; `opts` includes `seek`, `filters`, `volume`, and an internal cancellation signal. `/play` autocomplete uses `src/music/autocomplete.js` with a bounded in-memory LRU and keyless YouTube suggestions. `player.js` resolves URLs through each source's `canHandle(query)` predicate and falls back to YouTube for search text; resolved tracks retain their source name so playback and prefetch use the matching module. Register new source modules in the `sources` array. The generic yt-dlp source accepts public non-YouTube HTTP(S) URLs only; `src/music/sources/url-safety.js` blocks private and reserved IPv4/IPv6, mapped, NAT64, 6to4, and DNS results; DNS rebinding/redirects cannot be fully prevented without pinned-IP requests. Per-guild filter presets are built by `src/music/filters.js`; `/filter add|remove|clear` restarts the current track at its elapsed position. Loudness leveling is ON by default (`/normalize enabled level:soft|normal|loud`, settings `levelingEnabled` + `loudnessLevel`): every stream gets `loudnorm=I=<-21|-18|-15>:TP=-2:LRA=7` (default soft, -21 LUFS). Measured on 6 real songs: raw spread 14.7 LU (-12.9 to -27.6 LUFS, peaks up to +0.6 dBFS) became 2.1 LU; cost is a forced re-encode (~4% of one core per playing server vs 0.1% for the Opus copy path, so the copy path is only used when leveling is off). YouTube/yt-dlp expose no loudness metadata, so measuring in ffmpeg is required; `dynaudnorm` was tested and left a 7 LU spread. The card only shows a leveling badge when it differs from the default. `/sponsorblock enabled:true|false` uses a bounded in-memory cache and elapsed-time timers to skip supported YouTube segments; failures are silent. `/autoplay enabled:true|false` resolves one not-recently-played track from YouTube Mix when the queue empties and keeps the last 50 video IDs per guild in memory. `/lyrics [title]` uses LRCLIB with a pure title cleaner and ephemeral paginated lyrics. Each `GuildQueue` keeps the last 25 played tracks in memory; `/history` lists them and `/replay <position>` queues a clone. `/playlist` uses an atomic per-user `data/playlists.json` store (25 lists/user, 200 tracks/list, names <=32 chars); the persistent store singleton loads at startup. The Now Playing Heart button saves the current track into that clicker’s `favorites` playlist; `/favorites` plays it. `/skip` uses one vote per human with a majority threshold when >2 humans listen; requesters, configured DJ role, and ManageGuild bypass. `/forceskip` is ManageGuild-only. Direct audio paths can be played as live radio through ffmpeg; live tracks display `LIVE` and cannot be sought. Spotify track/album/playlist URLs use keyless embed metadata; later playlist tracks are resolved to YouTube lazily when they reach playback. `prefetch(track, { signal })` may cache a direct audio URL for a queued track; `kill` must terminate child processes.
- `scripts/update-ytdlp.js` - platform-specific yt-dlp binary download into `bin/` (gitignored); its `dest` path is imported by the YouTube source, which falls back to `yt-dlp` on PATH. `src/index.js` logs uncaught exceptions and performs queue/process cleanup on SIGTERM/SIGINT.

## Gotchas

- `@discordjs/voice` must be >= 0.19 (with `@snazzah/davey`): Discord requires DAVE end-to-end voice encryption, and 0.18 connects and "plays" but produces silent audio. Check with `generateDependencyReport()`.
- **Songs cut off early (fixed):** YouTube drops long direct-URL downloads (~2 min) while ffmpeg waits for the player; ffmpeg then logs `Error during demuxing: I/O error` and the song ends 30-60 s early. Every http(s) ffmpeg input therefore gets `HTTP_RECONNECT_ARGS` (`-reconnect 1 -reconnect_streamed 1 -reconnect_at_eof 1 -reconnect_delay_max 5`, as INPUT options before `-i`). `GuildQueue.resumeIfEndedEarly()` is a safety net: a finite song whose stream ends >10 s before its length resumes from where it stopped (max 2 times). Reproduce/verify by consuming a full song at ~real-time speed (a fast consumer hides the bug); `readrate` does not help.
- Settings: `store.set` persists only the keys that were explicitly set, so changing a default later reaches servers that already have a saved file. (Old files froze every default; that is why the leveling flag has its own key, `levelingEnabled`, and a stale `autoNormalize: false` is ignored.)
- **ffmpeg must never open a network URL itself:** the static ffmpeg build segfaults (SIGSEGV, "ffmpeg exited with code null") on hosts where it has to resolve a host name (reproduced in WSL: even `ffmpeg -i http://example.com/` crashes, piped/local input is fine). `src/music/http-feed.js` downloads in Node (4 MB ranged chunks that resume at the same byte after a drop; live streams are one plain GET) and pipes into ffmpeg `-i pipe:0`, for songs (`spawnStream`) and radio (`spawnRadio`). yt-dlp also unpacks itself into `data/tmp` on Linux (`src/ytdlp-env.js`) because small/RAM-backed /tmp made it fail with `Failed to extract ..._ARC4.abi3.so`.
- YouTube may block datacenter IPs on the host; the mitigation is a `cookies.txt` via `YTDLP_COOKIES`.
- `ffmpeg-static`'s install script may be skipped by npm (`allowScripts` warning), but the binary still ends up present; verify `node_modules/ffmpeg-static/ffmpeg(.exe)` exists if playback fails.
